Proof of Authority

Known validators make scheduled authority a better fit.

prefix-derived validator set→(height + view) % N→scheduled proposer signs→peers verify

PoA answers who may propose and removes the mining race.

The second consensus gap

Authorship is not agreement.

valid producer signature≠network-wide irreversible decision

Plain PoA proves who proposed a block. It does not prove that enough validators committed to it.

Quorum finality

Finality requires a supermajority over the same header.

def quorum_size(n: int) -> int:
    return (2 * n) // 3 + 1

validators = self.validator_set(block.index)
committed = block.commit_signers() & validators
return len(committed) >= quorum_size(len(validators))

  2. validate
  3. commit-sign
  4. reach quorum

Liveness problem

What if the scheduled proposer disappears?

height hview 0scheduled proposerOFFLINEno block

Safety cannot help the chain progress when the only permitted proposer stalls.

View change

A quorum justifies rotating to another proposer.

signed view-change votes→quorum→view + 1→deterministic rotation→new proposal

Votes bind both height and view. This is a course-project BFT-style mechanism—not a claim of complete production PBFT equivalence.

Benchmark · method

Every number needs a controlled baseline.

External blockchain TPS would be misleading: hardware, geography, payloads and finality definitions differ. GradED instead compares one changed condition while keeping its own implementation and environment fixed.

Benchmark · 01

Finality vs validator count.

A block is final only once ⌊2n/3⌋+1 validators have gossiped commit signatures for it. For each N ∈ {4, 7, 10, 13} this launches an isolated cluster of N real validators, proposes a series of blocks, measures each block's finalized_at − proposed_at from the proposer's own consensus events, then shuts the cluster down. The point is the shape: quorum finalization is not free as the committee grows — the commit round is all-to-all.

BASELINE N=4vsVARIABLE N=7 · 10 · 13
takes ~1–2 min: four clusters are started and stopped
not run yet

Benchmark · 02

Convergence latency.

Finality is deterministic, so once a block holds a quorum every honest node agrees on it — the only question is when. On the running cluster, each block's agreement window is max(finalized_at) − min(finalized_at) across every node: from the first node to observe the quorum to the last. That is pure commit-gossip propagation, not re-agreement.

CONSENSUS propose → finalvsPROPAGATION first → last node
takes ~5–15s on the live cluster
not run yet

Benchmark · 03

The cost of a view change.

Liveness does not depend on any single leader: if the scheduled proposer stalls, validators sign view-change votes and a quorum rotates the proposer. This measures a happy-path block against one where that scheduled proposer is taken offline — from the stall being acted on to the replacement block's finality. Safety is untouched by the rotation; what it costs is the wait.

BASELINE view 0vsFAILURE PATH leader offline
takes ~15–30s on its own 7-validator cluster

Final project statement

GradED is not a decentralized university.

It is an application-specific blockchain protocol that records why a competence credential was issued, who supported it, under which rubric, with what weight, and under which trust assumptions.
