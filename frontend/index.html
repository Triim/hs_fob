GradED — reproducible, expert-attested competence certification on a blockchain.

The problem

You can learn anything on your own.

But there's no way to turn that into a recognized credential — the way a degree does.

The idea

Reproducible work, attested by experts.

Domain experts sign item-level attestations against a shared rubric. Enough weighted expert support issues a certificate.

What's submitted

A reproducible artifact, hashed on-chain.

Only its hash lives on the chain. The file itself is never stored.

Three distinct roles

Competence, credibility, authority.

  • Competence reputation
  • Attester credibility
  • Consensus authority

Competence becomes authority only through quorum-approved, rate-limited promotion.

What makes it different

Not a diploma-NFT.

  • Merkle-committed rubric
  • Item-level attestations
  • Domain reputation
  • Weighted support
  • Reviewer accountability
  • Evidence-based slashing
  • Protocol-issued certificate

An honest limit

It doesn't replace institutions.

Blockchain makes expert action transparent and verifiable — it can't judge whether an honest review is correct.

Guarantee · 01

Cryptographic authorship.

Every participant transaction is Ed25519-signed. Unsigned or unknown-type transactions are rejected — fail-closed.

Guarantee · 02

Consensus safety.

PoA-proposed, BFT-quorum-finalized (⌊2n/3⌋+1). No two conflicting blocks finalize; finalized blocks are irreversible.

Guarantee · 03

Liveness.

View-change rotates the proposer when one stalls.

Guarantee · 04

Deterministic certificates.

Re-derived from the chain prefix, never trusted from a producer. Duplicate or unearned certificates are rejected.

Guarantee · 05

Economic accountability.

Bonded stake and rewards for contributing attestations. Evidence-based quorum slashing burns stake and reputation.

Guarantee · 06

Collusion resistance.

A single cross-attesting cluster's contribution is capped.

Known limits

Where the guarantees end.

  • Sybil resistance needs an external proof-of-personhood.
  • Honesty & quality of a review has no on-chain oracle.
  • The token layer is demonstrative, not a real economy.
  • Finality assumes synchronous commit collection.
  • Institutional legitimacy is a social problem blockchain can't solve.

Benchmark · 01

Finality vs validator count.

A block is final only once ⌊2n/3⌋+1 validators have gossiped commit signatures for it. For each N ∈ {4, 7, 10, 13} this launches an isolated cluster of N real validators, proposes a series of blocks, measures each block's finalized_at − proposed_at from the proposer's own consensus events, then shuts the cluster down. The point is the shape: quorum finalization is not free as the committee grows — the commit round is all-to-all.

takes ~1–2 min: four clusters are started and stopped

Benchmark · 02

Convergence latency.

Finality is deterministic, so once a block holds a quorum every honest node agrees on it — the only question is when. On the running cluster, each block's agreement window is max(finalized_at) − min(finalized_at) across every node: from the first node to observe the quorum to the last. That is pure commit-gossip propagation, not re-agreement.

takes ~5–15s on the live cluster
not run yet

Benchmark · 03

The cost of a view change.

Liveness does not depend on any single leader: if the scheduled proposer stalls, validators sign view-change votes and a quorum rotates the proposer. This measures a happy-path block against one where that scheduled proposer is taken offline — from the stall being acted on to the replacement block's finality. Safety is untouched by the rotation; what it costs is the wait.

takes ~15–30s on its own 7-validator cluster
